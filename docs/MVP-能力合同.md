# RideMind 自用试骑 MVP 能力合同

> 版本：0.1｜日期：2026-10-15｜状态：可实施

## CAPABILITY

作为一名独自骑行者，用户可以在 Android 手机上开始一次骑行，让应用在锁屏和音乐播放期间记录基础骑行状态，并在少量、可解释的情境节点用系统 TTS 进行短语音陪伴；用户能随时选择简洁、标准或健谈模式、临时静音，并在结束后查看本次播报及给出反馈。

本 MVP 的唯一产品验证目标是：**情境化语音是否比固定周期数据播报更有陪伴感，且不会明显打扰骑行。**

## CONSTRAINTS

### 固定产品规则

- Android 单平台、单用户、自用试骑，不做账号系统。
- 无心率带也能完成完整体验；GPS 是唯一必需传感器。
- 所有开口决策本地完成；断网不影响核心体验。
- 角色层只能改变措辞，不能改变速度、距离、阶段和事件优先级。
- 不声称识别用户心理、疲劳或医学状态。
- 不承诺道路危险识别、实时路况或导航安全。
- 下坡或高速阶段禁止社交闲聊；应用只做陪伴静默，不以语音代替观察道路。
- 每条候选播报必须有触发原因、优先级、有效期、去重键和可打断性。
- 过期播报必须丢弃；静音后非关键播报不得播放。
- 轨迹、骑行数据和反馈只保存在本机。

### MVP 陪伴事件

1. 出发欢迎：移动成立后一次。
2. 进入巡航：持续移动且速度稳定后一次。
3. 爬坡鼓励：基于平滑海拔变化估算，置信度不足时不触发。
4. 爬坡结束：从爬坡回到平缓后一次。
5. 距离里程碑：每 5 km 一次。
6. 后半程陪伴：骑行满 30 分钟后一次。
7. 重新出发：暂停后恢复移动时一次。
8. 结束回顾：用户结束会话时一次。

### 发言预算

- 简洁：社交类每小时最多 2 次；保留出发、里程碑、结束。
- 标准：社交类每小时最多 6 次。
- 健谈：社交类每小时最多 10 次。
- 非必要播报全局间隔至少 90 秒。
- 同类型事件默认冷却 10 分钟。
- 高速/下坡门控优先于发言预算。

## IMPLEMENTATION CONTRACT

### Actors

- 骑手：开始、暂停、恢复、结束骑行，选择陪伴模式，临时静音，骑后反馈。
- Android 前台服务：位置采集、会话状态、阶段推断、播报仲裁。
- 系统 TTS：本地语音输出。
- Android AudioManager：短暂获取音频焦点并允许其他媒体 duck。

### Surfaces

- 骑行主页：权限状态、会话状态、时长、距离、当前/平均速度、阶段、开始/暂停/结束。
- 陪伴控制：简洁/标准/健谈；静音 10 分钟；立即恢复。
- 事件日志：时间、触发、实际话术、是否播出或丢弃原因。
- 骑后复盘：总时长、距离、均速、播报列表；每条可标记“有用/打扰”。

### States and transitions

#### Ride session

`IDLE → RECORDING ↔ PAUSED → FINISHED`

- 只有用户操作才能开始和结束。
- 应用异常退出后，本 MVP 保存已完成的摘要和事件日志；连续录制恢复列为后续能力。

#### Ride phase

`STATIONARY → STARTING → CRUISING → CLIMBING → RECOVERING`

- 阶段由纯 Kotlin 引擎根据最近样本推断。
- 数据质量不足时保持当前阶段或回到 `STARTING`，不猜测。

#### Announcement

`CANDIDATE → ASSESS → SAY / DROP`

丢弃原因至少包括：`MUTED`、`UNSAFE_CONTEXT`、`COOLDOWN`、`BUDGET_EXHAUSTED`、`EXPIRED`、`DUPLICATE`。

### Inputs

每个位置样本：

- 单调时间；
- 纬度、经度；
- Android 提供的速度及精度；
- 海拔及垂直精度（存在时）；
- 是否为模拟/低质量样本。

### Outputs

- `RideSnapshot`：时长、距离、当前速度、平均速度、估算坡度、阶段。
- `AnnouncementDecision`：播放或丢弃、原因、候选事件。
- `RideSummary`：结束统计、实际播报和反馈。

### Data ownership

- MVP 使用本机 JSON 文件保存最近一次骑行摘要、事件与反馈。
- 不上传原始轨迹，不接入 LLM，不收集原始音频。
- Android 权限只申请精确位置、通知和前台位置服务所需权限。

### Failure and recovery

- 无 TTS 引擎或初始化失败：继续记录并在界面展示错误，事件标记为未播。
- 定位权限拒绝：禁止开始并说明原因。
- GPS 质量差：不累计明显跳点，不触发坡度事件。
- 音频焦点被拒绝：本次播报放弃，不抢占通话或导航。
- 服务销毁：保存当前摘要；通知用户会话已停止。

### Observability

每个候选事件记录：

- 创建时间；
- 触发事实；
- 决策结果；
- 丢弃原因；
- 实际话术；
- TTS 开始/结束或错误。

## NON-GOALS

- 开放式 AI 对话、云端 LLM 和长期人格记忆；
- 高德路线、转弯导航、实时交通和天气；
- 心理状态、HRV、疲劳诊断；
- 功率计、踏频计和完整训练计划；
- 自动事故检测或紧急呼叫；
- iOS/KMP 交付；
- 社交、账号、云同步；
- 应用商店发布质量。

## OPEN QUESTIONS

以下不阻塞首版，由本人试骑数据决定：

1. 标准模式每小时 6 次是否太多？
2. 5 km 里程碑是否应改成可配置？
3. 只依靠手机 GPS 海拔是否足以稳定识别坡段？
4. 系统 TTS 的音色是否足够产生陪伴感？
5. 是否需要在第二版接入 H303 心率以改善情境，而非做心理推断？

## HANDOFF

能力边界已足够直接实施。先以纯 Kotlin 测试锁定阶段识别和播报导演，再接 Android 前台服务、系统 TTS 和 Compose UI。完成后以本人三次真实骑行为首轮门禁，不在首版加入 LLM。
